Zadig v5.1.0 was officially released on November 19, 2026.

## Feature List

**AI Agents**
- Newly introduced Zadig AI, covering scenarios such as workflow error analysis and project initialization
- AI environment inspection and AI efficiency inspection are integrated into Zadig AI
- AI code review rules support same-level merging on the same path and cross-level override
- AI code review supports writing comments back as a bot
- Insights add AI review analysis
- Insights add Zadig AI analysis
- AI code review notifications include review results
- Feishu Project DevOps+ plugin sync supports AI tasks
- AI Release Specialist adapts to the Apollo create-namespace operation

**Services and Environments**
- Helm service configuration supports updating the template in use
- Helm project service details support DaemonSet resources
- CR resource deployment supports multi-segment image fields
- Instantiated Helm Chart deployment supports automatic Values synchronization
- Helm service updates support the UpgradeCRDs option

**Workflow**
- Workflow dynamic variables support multi-select
- General script execution tasks support running multiple tasks by variable group
- The image build step in build configuration adds a proxy toggle
- Helm Values support variable rendering when executing a workflow
- APISIX tasks skip tasks that have already succeeded when retrying after a failure
- The APISIX execution page displays the resource ID
- APISIX proto releases add an optional compatibility hint
- APISIX and Apollo configuration changes show create and update indicators during execution
- Apollo configuration change tasks support creating a Namespace
- Added a deployment order for K8s resources within the same service to keep deployments stable

**Release Plan**
- Release plans support custom fields
- A prompt is shown for completed release items when a release plan is edited again
- Several interaction improvements on the release plan page
- Release item owners in a release plan can be configured as user groups, and only the release owner can modify them
- Fixed an issue where approval configuration could still be modified when creating a release plan without approval-edit permission
- Fixed an issue where selected images were reset to the default value when adding a deployment service while re-editing a release plan
- Fixed an issue where concurrent updates to the same Apollo configuration item from multiple release plans overwrote each other

**System Integration and Openness**
- OpenAPI supports workflow deployment tasks that include service configuration updates
- OpenAPI/CLI/MCP support project updates and project group management
- OpenAPI/CLI/MCP support service catalog management
- OpenAPI/CLI/MCP support getting service Values, version differences, and update operations
- OpenAPI/CLI/MCP support custom image and build template management
- OpenAPI/CLI/MCP support service rollback
- CLI/MCP support OAuth authentication
- CLI supports creating a service from a Helm template and adding it to a test environment
- CLI supports creating services by batch-importing Values files with a template
- Improved CLI workflow log queries
- CLI supports viewing Helm environment service details
- MCP supports viewing workflow logs
- Feishu and Lark account systems support configuring the username attribute
- Host management supports specifying a project scope
- Proxy configuration supports HTTPS and SOCKS5
- Cluster-scheduled workflow tasks support configuring the project scope separately
- Cluster management supports RRSA configuration for Alibaba Cloud clusters

**Security and Compliance**
- Git credentials are hidden in build Pods
- Corresponding permission items are added for system integrations
- Improved zadig-review-agent so that it does not read sensitive files
- Commands from container debugging and host login are included in audit logs
- Improved system operation logs and enhanced query capabilities
- Fixed security vulnerabilities such as authentication bypass and unauthorized access, and strengthened authentication and permission checks
- Upgraded base images of Zadig components to fix known security vulnerabilities and improve stability
- Upgraded core components and dependencies such as Go, Docker, and Helm to fix known security vulnerabilities

**Improvements and Fixes**
- Improved image rollback information
- Improved the deletion prompt for imported-only services
- Improved the interaction of environment selection and Helm service search
- Improved remote branch search when importing service Values from GitLab
- Improved the Helm Values editor to format and render config that contains line breaks
- Improved Values preview for instantiated Helm deployment services
- Improved the interaction of the "use latest service configuration" option when updating Helm Values in an environment
- Improved Deployment status detection
- Fixed duplicate projects returned by project list pagination
- Fixed incomplete display when historical logs are too large
- Fixed runtime errors in Helm project workflow deployment tasks
- Fixed a Helm deployment prompt that the kube version is too low
- Fixed an issue where Helm services containing images with the same name could not be updated together
- Fixed occasional workflow variable mix-ups
- Fixed stale commit_id remaining after adding a service or switching branches on the workflow page
- Fixed an additional properties forbidden error when updating an APISIX proto
- Fixed inconsistent comparison after APISIX configuration content changed across operating systems
- Fixed an error when creating a trigger for a code repository that uses a self-signed certificate
- Fixed a save error when creating a workflow strongly bound to a built-in template
- Fixed workflow variables being cleared after switching from runtime input to a fixed value
- Fixed an issue where no resources were visible after adding a user group permission in a project
- Fixed aslan restarting continuously when updating an environment after the Helm project service configuration no longer exists
- Fixed subchart CRDs that were not enabled being overwritten during Helm deployment
- Fixed host projects that could select an image registry in the build configuration but failed at execution
- Fixed AWS image registry AK/SK changes not taking effect because of cache
- Fixed incorrect ready Pod counts displayed for Deployments
- Fixed service configuration with an image-registry single-select variable becoming invalid after being added to an environment
- Fixed credentials for multiple registries in the same Namespace being overwritten by the Zadig configuration
- Fixed other services being deleted by mistake when updating them after a Helm configuration was deleted
- Fixed required-variable validation for general tasks with multiple task types on a service component
- Fixed unexpected EOF during high-concurrency image distribution
- Fixed cluster status staying disconnected and not reconnecting automatically after a Redis failure
- Fixed task timeouts caused by Agent recreation when updating a cluster scheduling policy
- Various other fixes and improvements

## Version Upgrade Process

::: warning
If MongoDB is deployed in Replica Set mode, please confirm that system databases such as admin/local/config/test are not used as Zadig's business database. If they are used, please manually migrate the data first.

If the current system version < v5.0.0, please upgrade to v5.0.0 first. For specific upgrade steps, please refer to [v5.0.0 Upgrade Method](/en/Zadig%20v5.1/release-notes/v5.0.0/#version-upgrade-process), and then upgrade to v5.1.0 using the following method.
:::

::: tip
If both aslan and dind fail to start during the upgrade, scale the dind replicas to 0 first to resolve the mutual dependency between the two components at startup.
:::
