Zadig v5.0.0 was officially released on July 31, 2026.

## Feature List

**AI Agents**
- AI Release Specialist: analyzes workflow tasks with change and release context to produce risk conclusions, with human confirmation support
- AI Review Specialist: built-in AI review in the code review module, with configurable rules and results written back to MR comments
- AI Task: workflows can connect to custom Agents or models to run intelligent tasks
- Zadig CLI & Skills Phase 1: open capabilities for external Agent invocation

**Services and Environments**
- Service management and workflow deployment support CR resources
- Environment service view supports displaying Job and DaemonSet resources
- Built-in cluster name variable added to service configuration
- Helm environments add service configuration drift detection
- YAML environments allow deleting services without deleting specified resources
- Host environments support aliases

**Workflow**
- Workflows support strong binding with templates
- Workflows support task-level notifications
- Deployment tasks support DaemonSet resource updates
- APISIX change tasks support outputting configuration ID information
- JIRA tasks support status display
- Jenkins tasks support listing jobs inside folders
- Global variables support dynamic variable types
- Variables can be marked as required
- Tasks and notifications can retrieve Git trigger Payload information
- Execution remarks can be marked as required
- Execution record column fields support associating release plans
- Approval titles support customization
- Git triggers support regex matching for Tag triggers
- Execution preparation stage supports displaying Pod events
- Test tasks support variable input

**Release Plan**
- Rich text supports inserting tables
- External system Hook payloads include release item owner information
- More detailed operation logs
- Prompt added when multiple users edit simultaneously

**System Integration and Openness**
- AI model integration supports multiple model providers
- Chart repositories support configuring public Chart repositories
- Account system supports integrating overseas Lark
- Separate permission control for operation logs
- Dind supports TLS
- Enterprise management adds a version information toggle
- Execute workflow OpenAPI supports passing through common task code information
- New OpenAPI to create K8s YAML services from code repositories
- New OpenAPI to create Helm services from private repos / public repos / Chart repositories
- New OpenAPI to create and update custom workflows
- New OpenAPI to query workflow manual execution context and execute manual stages
- New OpenAPI to get the current user identity

**Improvements and Fixes**
- Improved efficiency data calculation by excluding debug workflow data
- Improved notification card style for waiting for manual execution status
- Improved APISIX change task configuration and execution operations
- Improved DMS task ticket search in workflows
- Improved copy and paste issues in container debugging
- Improved Apollo YAML configuration validation
- Improved Nacos configuration error messages
- Improved full image display in image distribution after saving a release plan draft
- Added image existence check before service rollback
- Show Pod count in container service deployment logs
- Fixed release plans not showing workflow execution records and links
- Fixed permission issues when drag-reordering release plans
- Fixed inconsistent personnel information and modification time in project overview
- Fixed inability to select Jenkins Jobs in release plans and triggers
- Fixed incomplete cleanup when calling the delete service OpenAPI
- Fixed execute workflow OpenAPI not including approval initiator information
- Fixed error when reselecting the root directory for Chart templates
- Fixed incorrect multi-select variable values when cloning workflow debug tasks
- Fixed status being cleared during the manual execution stage of blue-green deployment
- Fixed test pass rate judgment failing when tests run on hosts
- Fixed errors when running code scans on hosts
- Various other fixes and improvements


## Version Upgrade Process

::: warning
If MongoDB is deployed in Replica Set mode, please confirm that system databases such as admin/local/config/test are not used as Zadig's business database. If they are used, please manually migrate the data first.

If the current system version < v4.3.0, please upgrade to v4.3.0 first. For specific upgrade steps, please refer to [v4.3.0 Upgrade Method](/en/Zadig%20v5.0/release-notes/v4.3.0/#version-upgrade-process), and then upgrade to v5.0.0 using the following method.
:::
