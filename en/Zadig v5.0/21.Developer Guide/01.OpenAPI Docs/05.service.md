## Get Service List

### Test Service

**Request**

```
GET /openapi/service/yaml/services?projectKey=<projectKey>
```
**Query Parameter Description**

| Parameter Name | Type   | Description   | Required |
| -------------- | ------ | ------------- | -------- |
| `projectKey`   | string | Project Key   | Yes      |

**Response Description**

| Parameter Name   | Type                        | Description                        |
| ---------------- | --------------------------- | ----------------------------------- |
| `service_name`   | string                      | Service name                       |
| `type`           | string                      | Service type, fixed value `k8s`     |
| `containers`     | [][Container](#Container-1) | List of service components          |

<h4 id="Container-1">Container Parameter Description</h4>

| Parameter Name | Type   | Description                |
| -------------- | ------ | -------------------------- |
| `name`         | string | Service component name     |
| `image`        | string | Service component image    |
| `image_name`   | string | Service component image name |

**Response Example**

::: details
```json
{
    "service": [
        {
            "service_name": "service-1",
            "type": "k8s",
            "containers": [
                {
                    "name": "myapp-1",
                    "image": "koderover.tencentcloudcr.com/koderover-demo/myapp-1:v0.1__linux_amd64",
                    "image_name": "myapp-1"
                }
            ]
        }
    ]
}
```
:::

## Get Service Details

### Test Service

**Request**

```
GET /openapi/service/yaml/:serviceName?projectKey=<projectKey>
```

**Path Parameter Description**

| Parameter Name | Type   | Description     | Required |
| -------------- | ------ | --------------- | -------- |
| `serviceName`  | string | Service name    | Yes      |

**Query Parameter Description**

| Parameter Name | Type   | Description     | Required |
| -------------- | ------ | --------------- | -------- |
| `projectKey`   | string | Project Key     | Yes      |

**Response Description**

| Parameter Name                 | Type                        | Description                   |
| ------------------------------ | --------------------------- | ----------------------------- |
| `service_name`                 | string                      | Service name                  |
| `created_by`                   | string                      | Service creator               |
| `created_time`                 | int                         | Service creation time         |
| `type`                         | string                      | Service type, fixed value `k8s` |
| `containers`                   | [][Container](#Container-3) | Service component list         |
| `service_variable_kvs`         | [][KeyVal](#KeyVal-1)       | Service variable list          |
| `yaml`                         | string                      | Service configuration YAML content |

<h4 id="Container-3">Container Parameter Description</h4>

| Parameter Name | Type   | Description                |
| -------------- | ------ | -------------------------- |

| Parameter Name | Description                                               | Type     | Required |
| -------------- | --------------------------------------------------------- | -------- | -------- |
| `key`          | Variable key                                               | string   | Yes      |
| `value`        | Variable value, if there is nested value, use json format    | any      | Yes      |
| `type`         | Variable value type, there are four types: bool, string, enum, yaml | string   | Yes      |
| `options`      | Variable optional value list, this field has meaning when `type` is `enum` | []string | No       |
| `desc`         | Variable description information                             | String   | No       |

**Response Example**

:::details

```json

    "containers": [
        {
            "name": "service2",
            "image": "koderover.******.com/koderover-demo/service2:latest",
            "image_name": "service2"
        }
    ],
    "service_variable_kvs": [
        {
            "key": "cpuLimit",
            "value": "55m",
            "type": "string",
            "options": [],
            "desc": ""
        }
```

## Create New Service Using Template

### Test Service

**Request**

```
POST /openapi/service/template/load/yaml
```

**Body Parameter Description**

| Parameter Name  | Description             | Type                  | Required |
| --------------- | ----------------------- | --------------------- | -------- |
| `service_name`  | Service name            | string                | Yes      |
| `project_key`   | Project key             | string                | Yes      |
| `template_name` | K8s Yaml Template Name  | string                | Yes      |
| `auto_sync`     | Auto sync switch         | bool                  | No       |
| `variable_yaml` | Template variable information | [][KeyVal](#KeyVal-5) | No       |

<h4 id="KeyVal-5">KeyVal Parameter Description</h4>

| Parameter Name | Description                                 | Type   | Required |
| -------------- | ------------------------------------------- | ------ | -------- |
| `key`          | Variable key value                           | string | Yes      |
| `value`        | Variable value, if there is nested value, use json format | any    | Yes      |

**Body Parameter Example**

Use template `microservice-template` to create service `service1` for project `demo`:

::: details
``` json
{
    "service_name": "service1",
    "project_key":"demo",
    "template_name": "microservice-template",
    "auto_sync": true,
    "variable_yaml": [
        {
            "key": "cpuLimit",
            "value": "100m"
        },
        {
            "key": "memoryLimit",
            "value": "100Mi"
        },
        {
            "key": "port",
            "value": "20221"
        }
    ]
}
```
:::

**Return**

```json
{
  "message": "success"
}
```

## Create Helm Service

Create Helm services from a code repository, public repository, or Chart repository.

**Request**

```
POST /openapi/service/helm/load?projectKey=<projectKey>
```

**Query Parameter Description**

| Parameter Name | Type   | Description | Required |
| -------------- | ------ | ----------- | -------- |
| `projectKey`   | string | Project Key | Yes      |

**Body Parameters**

| Parameter Name | Description                                                                 | Type   | Required |
| -------------- | --------------------------------------------------------------------------- | ------ | -------- |
| `source`       | Service source enum. See the value mapping below                          | string | Yes      |
| `production`   | Whether to create a production service; defaults to `false`                 | bool   | No       |
| `createFrom`   | Service source configuration. See the following sections for fields by `source` | object | Yes      |

The request field `name` is not used when creating services from these sources. For code and public repositories, each service name is read from the corresponding `Chart.yaml`; for a Chart repository, `chartName` is used as the service name.

<h4 id="OpenAPIHelmLoadSource-1">source Values</h4>

| Value              | Meaning                                                            |
| ------------------ | ------------------------------------------------------------------ |
| `repo`             | An integrated GitHub, GitLab, or generic Git code source of type `other` |
| `gerrit`           | An integrated Gerrit code source                                  |
| `gitee`            | An integrated Gitee code source                                   |
| `gitee-enterprise` | An integrated Gitee Enterprise code source                        |
| `publicRepo`       | A public GitHub repository that does not require code source integration |
| `chartRepo`        | An integrated Chart repository                                    |

Here, `repo` is an API enum value rather than a generic term for all code repository sources.

<h4 id="OpenAPICreateFromRepo-1">createFrom Parameters for Integrated Code Sources</h4>

This applies when `source` is `repo`, `gerrit`, `gitee`, or `gitee-enterprise`.

| Parameter Name | Description                                                          | Type     | Required |
| -------------- | -------------------------------------------------------------------- | -------- | -------- |
| `codehostID`   | Codehost ID                                                          | int      | Yes      |
| `owner`        | Repository owner or organization                                     | string   | Yes      |
| `namespace`    | Repository namespace, used for multi-level GitLab groups. If empty, `owner` is used | string   | No       |
| `repo`         | Repository name                                                      | string   | Yes      |
| `branch`       | Branch name                                                          | string   | Yes      |
| `paths`        | Chart path list. Multiple paths are supported                        | []string | Yes      |

<h4 id="OpenAPICreateFromPublicRepo-1">createFrom Parameters When source Is publicRepo</h4>

| Parameter Name | Description                                   | Type     | Required |
| -------------- | --------------------------------------------- | -------- | -------- |
| `repoLink`     | Public repository URL                         | string   | Yes      |
| `paths`        | Chart path list. Multiple paths are supported | []string | Yes      |

<h4 id="OpenAPICreateFromChartRepo-1">createFrom Parameters When source Is chartRepo</h4>

| Parameter Name  | Description           | Type   | Required |
| --------------- | --------------------- | ------ | -------- |
| `chartRepoName` | Chart repository name | string | Yes      |
| `chartName`     | Chart name            | string | Yes      |
| `chartVersion`  | Chart version constraint. If empty, no version is specified and Helm resolves an available version | string | No |

**Body Parameter Example**

Create a Helm service for project `demo` from the `main` branch of codehost `1`:

::: details
``` json
{
    "source": "repo",
    "production": false,
    "createFrom": {
        "codehostID": 1,
        "owner": "koderover",
        "repo": "helm-charts",
        "branch": "main",
        "paths": [
            "charts/backend"
        ]
    }
}
```
:::

**Response Description**

| Parameter Name    | Description                        | Type                                      |
| ----------------- | ---------------------------------- | ----------------------------------------- |
| `successServices` | List of services created successfully | []string                                |
| `failedServices`  | List of services that failed to create | [][FailedHelmService](#FailedHelmService-1) |

<h4 id="FailedHelmService-1">FailedHelmService Parameters</h4>

| Parameter Name | Description            | Type   |
| -------------- | ---------------------- | ------ |
| `path`         | Chart path that failed | string |
| `error`        | Failure reason         | string |

**Response Example**

::: details
```json
{
    "successServices": [
        "backend"
    ],
    "failedServices": []
}
```
:::
