## 介绍

Zadig MCP Server 将 Zadig 能力封装为 MCP 工具，可供 Cursor、Claude Code、Trae、VS Code、Codex、飞书 Aily 等 MCP 客户端调用。

Zadig MCP 提供 `stdio`、Streamable HTTP 两种主要接入方式，并提供旧 SSE 兼容端点，满足本地开发和远程共享服务两类场景。

## 使用说明

::: tip
- Zadig 版本需为 v4.2.0 或以上。
- 请在 Zadig 的**账号设置**中创建 API Token。
- 请将文中的 `https://your-zadig.com`、`https://mcp.your-company.com`、`your-token` 替换为实际值。
:::

MCP 可执行创建、更新、删除和运行工作流等操作。建议为每个用户或集成服务创建最小权限的 API Token；执行写操作前，请仔细确认目标项目、环境和参数。

远程请求中的 API Token 优先级如下：

1. `Authorization: Bearer <token>` 请求头。
2. URL 中的 `api_token` 参数。
3. MCP Server 进程的 `ZADIG_API_TOKEN` 环境变量。

::: warning
URL 中的 Token 可能被保存在客户端配置中，或记录在反向代理、网关及服务端访问日志中。仅在客户端无法设置请求 Header 时使用 `api_token`，并确保 URL 不会泄露。
:::

## 使用方式

| 方式 | 适用场景 |
| --- | --- |
| stdio | 本机安装，由 MCP 客户端启动 Zadig MCP Server。适用于 Cursor、Claude Code、Trae、VS Code、Codex 等客户端。 |
| Streamable HTTP | 部署为远程服务，通过 `/mcp` 提供 MCP 能力。适用于集中部署和支持远程 MCP 的客户端。 |
| SSE 兼容入口 | 仅适用于尚不支持 Streamable HTTP 的旧客户端。服务端仍使用 HTTP 方式启动。 |

### stdio

`stdio` 方式无需部署独立服务，MCP 客户端在本机启动 Zadig MCP Server。

#### 安装

Linux、macOS：

```sh
# 交互式安装：按提示输入 Zadig 地址和 Token，并选择需要配置的客户端
curl -fsSL https://resources.koderover.com/zadig-mcp/install.sh | sh
```

Windows PowerShell：

```powershell
irm https://resources.koderover.com/zadig-mcp/install.ps1 | iex
```

交互式安装会下载对应平台的二进制，并自动配置 Cursor、Claude Code、Trae、VS Code、Codex 中选定的客户端。完成后请重启客户端。

也可使用非交互式安装。该方式不会自动写入客户端配置：

```sh
curl -fsSL https://resources.koderover.com/zadig-mcp/install.sh | \
  ZADIG_API_HOST=https://your-zadig.com \
  ZADIG_API_TOKEN=your-token \
  sh
```

```powershell
$env:ZADIG_API_HOST="https://your-zadig.com"
$env:ZADIG_API_TOKEN="your-token"
irm https://resources.koderover.com/zadig-mcp/install.ps1 | iex
```

#### 验证

重启 MCP 客户端后，在客户端的 MCP Servers 页面确认 `zadig-mcp` 状态正常；也可输入“检查 Zadig MCP 服务是否可用”，由客户端调用 `zadig_ping` 验证连接。

![Zadig MCP Server 配置成功示例](./_images/mcp/mcp_settings_success_1.png)
![Zadig MCP Server 连接成功示例](./_images/mcp/mcp_settings_success_2.png)

若连接失败，请检查 Zadig 地址、API Token、二进制路径，以及配置中的 `-a 127.0.0.1:3000 -t stdio` 参数。

#### 使用

安装脚本会自动写入配置。需要手动配置时，请在客户端的 MCP 配置中添加以下内容，并将 `command` 改为实际二进制路径。Linux 和 macOS 的默认安装路径为 `~/.local/bin/zadig-mcp`。

```json
{
  "mcpServers": {
    "zadig-mcp": {
      "command": "/path/to/zadig-mcp",
      "args": ["--a", "127.0.0.1:3000", "--t", "stdio"],
      "env": {
        "ZADIG_API_HOST": "https://your-zadig.com",
        "ZADIG_API_TOKEN": "your-token"
      }
    }
  }
}
```

`-a` 和 `-t` 均为必填参数。`stdio` 模式不使用网络监听地址，`-a` 可固定填写 `127.0.0.1:3000`。

Codex 使用 TOML 格式。默认配置文件为 `~/.codex/config.toml`；若设置了 `CODEX_HOME`，则为 `$CODEX_HOME/config.toml`。

```toml
[mcp_servers.zadig-mcp]
command = "/path/to/zadig-mcp"
args = ["--a", "127.0.0.1:3000", "--t", "stdio"]

[mcp_servers.zadig-mcp.env]
ZADIG_API_HOST = "https://your-zadig.com"
ZADIG_API_TOKEN = "your-token"
```

配置完成后，可直接在客户端中使用自然语言操作 Zadig。例如：

```text
查询 demo 项目下的工作流列表
检查 demo 项目的 dev 环境中 web 服务状态
为 release 工作流生成可执行参数模板
```

### Streamable HTTP

Streamable HTTP 适用于集中部署 Zadig MCP Server。服务默认通过 `/mcp` 提供 MCP 接入，同时保留 `/sse` 和 `/message` 两个 SSE 兼容端点。

#### 部署

可在 Zadig 中创建 K8s 项目和环境，将以下 YAML 作为服务配置加入环境。请根据实际环境修改 `ZADIG_API_HOST`、镜像地址和版本、`MCP_ALLOWED_ORIGINS`、Ingress Class、域名及命名空间。

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: zadig-mcp-http-config
  labels:
    app: zadig-mcp-http
data:
  ZADIG_API_HOST: "https://your-zadig.com"
  MCP_TRANSPORT_TYPE: "http"
  MCP_LISTEN_ADDR: "0.0.0.0:3000"

  # Streamable HTTP 端点
  MCP_HTTP_ENDPOINT: "/mcp"

  # 旧 SSE 兼容端点
  MCP_SSE_ENDPOINT: "/sse"
  MCP_MESSAGE_ENDPOINT: "/message"

  # Web 应用调用时，填写该应用的 Origin；桌面 MCP 客户端通常可保持为空。
  MCP_ALLOWED_ORIGINS: ""

  # 审计默认关闭；确有需要时再启用。
  MCP_AUDIT_ENABLED: "false"
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: zadig-mcp-http
  labels:
    app: zadig-mcp-http
spec:
  replicas: 1
  selector:
    matchLabels:
      app: zadig-mcp-http
  template:
    metadata:
      labels:
        app: zadig-mcp-http
    spec:
      containers:
        - name: zadig-mcp
          image: koderover.tencentcloudcr.com/koderover-demo/zadig-mcp:0.1.9
          imagePullPolicy: IfNotPresent
          args:
            - "-t"
            - "$(MCP_TRANSPORT_TYPE)"
            - "-a"
            - "$(MCP_LISTEN_ADDR)"
          ports:
            - name: http
              containerPort: 3000
              protocol: TCP
          envFrom:
            - configMapRef:
                name: zadig-mcp-http-config
          resources:
            requests:
              cpu: 200m
              memory: 512Mi
            limits:
              cpu: 400m
              memory: 1024Mi
          readinessProbe:
            tcpSocket:
              port: 3000
            initialDelaySeconds: 5
            periodSeconds: 10
          livenessProbe:
            tcpSocket:
              port: 3000
            initialDelaySeconds: 10
            periodSeconds: 20
---
apiVersion: v1
kind: Service
metadata:
  name: zadig-mcp-http
  labels:
    app: zadig-mcp-http
spec:
  selector:
    app: zadig-mcp-http
  ports:
    - name: http
      port: 80
      targetPort: 3000
      protocol: TCP
  type: ClusterIP
---
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: zadig-mcp-http
  annotations:
    nginx.ingress.kubernetes.io/backend-protocol: "HTTP"
    nginx.ingress.kubernetes.io/service-upstream: "true"
    nginx.ingress.kubernetes.io/proxy-buffering: "off"
    nginx.ingress.kubernetes.io/proxy-request-buffering: "off"
    nginx.ingress.kubernetes.io/proxy-read-timeout: "3600"
    nginx.ingress.kubernetes.io/proxy-send-timeout: "3600"
    nginx.ingress.kubernetes.io/proxy-http-version: "1.1"
spec:
  ingressClassName: your-ingress-class
  rules:
    - host: mcp.your-company.com
      http:
        paths:
          - path: /mcp
            pathType: Prefix
            backend:
              service:
                name: zadig-mcp-http
                port:
                  number: 80
          - path: /sse
            pathType: Prefix
            backend:
              service:
                name: zadig-mcp-http
                port:
                  number: 80
          - path: /message
            pathType: Prefix
            backend:
              service:
                name: zadig-mcp-http
                port:
                  number: 80
```

示例中使用公开 demo 镜像 `koderover.tencentcloudcr.com/koderover-demo/zadig-mcp:0.1.9`，可按需替换为其他实际可访问的 Zadig MCP Server 镜像。若需要为服务配置默认 Token，可将 `ZADIG_API_TOKEN` 以 Kubernetes Secret 注入 Deployment。远程客户端也可以各自通过请求头或 URL 参数传入 Token。

#### 验证

1. 在 Zadig 环境中确认 `zadig-mcp-http` Pod 已就绪，且服务日志中没有启动错误。
2. 确认 Ingress 已生成并可访问 `https://mcp.your-company.com/mcp`。
3. 按下方客户端配置接入后，调用 `zadig_ping` 验证 MCP 连接，并尝试查询一个有权限访问的项目。

#### 使用

优先使用 `/mcp`，并通过请求 Header 传递 Token：

```json
{
  "mcpServers": {
    "zadig-mcp": {
      "url": "https://mcp.your-company.com/mcp",
      "headers": {
        "Authorization": "Bearer your-token"
      }
    }
  }
}
```

不支持自定义 Header 的客户端可以在 URL 中传递 Token：

```text
https://mcp.your-company.com/mcp?api_token=your-token
```

飞书 Aily 支持 Streamable HTTP，推荐新增 MCP 服务时使用上述 `/mcp` 地址。若通过 URL 传递 Token，可直接填写：

```text
https://mcp.your-company.com/mcp?api_token=your-token
```

保存后，可在 Aily 对话中调用 `zadig_ping` 或查询项目，验证连接和权限。

如需将 MCP 服务提供给浏览器侧的 Web 应用调用，应将该应用的完整 Origin 配置在 `MCP_ALLOWED_ORIGINS` 中。桌面 IDE 等 MCP 客户端通常不携带 `Origin`，无需该配置。多个 Origin 使用逗号分隔，不支持通配符。

#### 参数说明

| 配置项 | 说明 | 默认值 |
| --- | --- | --- |
| `ZADIG_API_HOST` | Zadig API 地址 | 无，必填 |
| `ZADIG_API_TOKEN` | 服务默认使用的 Zadig API Token | 无 |
| `MCP_HTTP_ENDPOINT` | Streamable HTTP 路径 | `/mcp` |
| `MCP_SSE_ENDPOINT` | SSE 兼容事件流路径 | `/sse` |
| `MCP_MESSAGE_ENDPOINT` | SSE 兼容消息路径 | `/message` |
| `MCP_ALLOWED_ORIGINS` | 允许访问的 Web 应用 Origin，多个值以逗号分隔 | 空 |
| `MCP_SESSION_IDLE_TTL` | Streamable HTTP 会话空闲回收时间，使用 Go duration 格式 | `30m` |
| `MCP_TRUSTED_PROXIES` | 可信反向代理的 CIDR/IP 列表，用于审计时识别客户端 IP | 空 |
| `MCP_AUDIT_ENABLED` | 是否启用审计日志，设为 `true` 时启用 | `false` |

启用审计后，建议将 `MCP_AUDIT_OUTPUT` 设为 `file`，并使用 `MCP_AUDIT_PATH` 指定日志文件。`MCP_AUDIT_BODY_MODE` 支持 `off`、`hash`、`redacted`、`raw`；`raw` 会记录原始业务数据，仅建议临时排障使用。

仅当服务确实部署在反向代理之后时，才配置 `MCP_TRUSTED_PROXIES`，并仅填写实际 Ingress 或负载均衡器的出口 IP/最小 CIDR。不要将整个私网网段设为可信代理，否则审计中的客户端 IP 可能被伪造。

### SSE

SSE 是为旧客户端保留的兼容接入方式。服务端不应使用已弃用的 `-t sse`；请按以下示例以 `-t http` 启动服务，并通过 `/sse` 和 `/message` 提供兼容服务。

#### 部署

在 Zadig 中将以下 YAML 作为服务配置加入环境。与 Streamable HTTP 部署相比，SSE 部署同样使用 `http` transport；差异仅在于客户端访问 `/sse`。请按实际环境修改地址、镜像、域名和 Ingress Class。

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: zadig-mcp-sse-config
  labels:
    app: zadig-mcp-sse
data:
  ZADIG_API_HOST: "https://your-zadig.com"
  MCP_TRANSPORT_TYPE: "http"
  MCP_LISTEN_ADDR: "0.0.0.0:3000"
  MCP_HTTP_ENDPOINT: "/mcp"
  MCP_SSE_ENDPOINT: "/sse"
  MCP_MESSAGE_ENDPOINT: "/message"
  MCP_ALLOWED_ORIGINS: ""
  MCP_AUDIT_ENABLED: "false"
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: zadig-mcp-sse
  labels:
    app: zadig-mcp-sse
spec:
  replicas: 1
  selector:
    matchLabels:
      app: zadig-mcp-sse
  template:
    metadata:
      labels:
        app: zadig-mcp-sse
    spec:
      containers:
        - name: zadig-mcp
          image: koderover.tencentcloudcr.com/koderover-demo/zadig-mcp:0.1.9
          imagePullPolicy: IfNotPresent
          args:
            - "-t"
            - "$(MCP_TRANSPORT_TYPE)"
            - "-a"
            - "$(MCP_LISTEN_ADDR)"
          ports:
            - name: http
              containerPort: 3000
          envFrom:
            - configMapRef:
                name: zadig-mcp-sse-config
          readinessProbe:
            tcpSocket:
              port: 3000
            initialDelaySeconds: 5
            periodSeconds: 10
          livenessProbe:
            tcpSocket:
              port: 3000
            initialDelaySeconds: 10
            periodSeconds: 20
---
apiVersion: v1
kind: Service
metadata:
  name: zadig-mcp-sse
spec:
  selector:
    app: zadig-mcp-sse
  ports:
    - name: http
      port: 80
      targetPort: 3000
  type: ClusterIP
---
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: zadig-mcp-sse
  annotations:
    nginx.ingress.kubernetes.io/proxy-buffering: "off"
    nginx.ingress.kubernetes.io/proxy-request-buffering: "off"
    nginx.ingress.kubernetes.io/proxy-read-timeout: "3600"
    nginx.ingress.kubernetes.io/proxy-send-timeout: "3600"
    nginx.ingress.kubernetes.io/proxy-http-version: "1.1"
spec:
  ingressClassName: your-ingress-class
  rules:
    - host: mcp.your-company.com
      http:
        paths:
          - path: /sse
            pathType: Prefix
            backend:
              service:
                name: zadig-mcp-sse
                port:
                  number: 80
          - path: /message
            pathType: Prefix
            backend:
              service:
                name: zadig-mcp-sse
                port:
                  number: 80
```

#### 验证

1. 在 Zadig 环境中确认 `zadig-mcp-sse` Pod 已就绪，服务日志没有启动错误。
2. 确认 Ingress 已将 `/sse` 和 `/message` 转发到服务，并关闭响应缓冲。
3. 在 SSE 客户端中配置下方地址，连接成功后调用 `zadig_ping` 或查询项目验证。

#### 使用

支持请求 Header 的客户端可配置：

```json
{
  "mcpServers": {
    "zadig-mcp": {
      "url": "https://mcp.your-company.com/sse",
      "headers": {
        "Authorization": "Bearer your-token"
      }
    }
  }
}
```

飞书 Aily 也支持该 SSE 兼容方式；使用仅支持填写 URL 的客户端时，可填写以下地址：

```text
https://mcp.your-company.com/sse?api_token=your-token
```

以飞书 Aily 使用 SSE 兼容入口为例：

1. 新增 MCP 服务。
2. 填写上述 SSE 地址。
3. 保存并验证连接；连接成功后，可通过对话查询 Zadig 项目、工作流和环境信息。
